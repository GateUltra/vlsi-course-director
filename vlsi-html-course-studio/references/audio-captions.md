# 多语言声音、音乐与独立字幕

制作真实配音、增加音色、修改文稿或处理字幕时阅读。具体案例见 [make_course_audio.py](../assets/placement-lesson06-source/scripts/make_course_audio.py)；它仍保留课程目录和声音配置，不能当作任意项目的即用 CLI。

## 选声：用真实句子验证角色和语气

先选一段约 20–30 秒的代表性文字，包含定义、术语、问题及结论。判断是否像在向学生解释、句尾是否僵硬、数字与缩写是否可懂，再决定语速／音高。演员感主要来自合适的文稿、停顿和声音选择，不靠大幅音高处理制造。

Placement 最终使用以下服务音色；这是已完成项目的记录，未来必须查看当时可用列表，而非假设名称永久有效：

| 轨道 ID | 服务音色 | 教学语言 |
| --- | --- | --- |
| `en_gb` | `en-GB-ThomasNeural` | 英式英语 |
| `en_us` | `en-US-GuyNeural` | 美式英语 |
| `en_in` | `en-IN-PrabhatNeural` | 印度英语 |
| `zh` | `zh-CN-YunxiNeural` | 普通话 |

案例通过 `edge_tts` 查询可用音色，并以自然 `rate='+0%'`、默认 pitch 合成。没有暗中替换不可用音色。名称代表合成服务身份，不代表某位公众人物、电视台或科学家本人配音。

执行在线合成前遵守当前任务已有授权：过去课程的授权不能自动扩展到无关材料；同一任务已明确授权则不重复索要许可。只发送所需文稿，保留服务、声音、设置及版本记录。新 skill 不应默认携带 API 密钥，也不把网络可用性或服务长期免费作为承诺。

## 语义片段与实测时钟

给每个 cue、每个声音分别生成音频。缓存键至少包括精确文字、音色 ID、语速、音高；服务版本、输出格式会影响输出时也加入。缓存中保留音频、指纹和可获得的词边界。下载先写临时文件，成功且非空才替换正式文件；网络重试应有上限并保留明确失败，不能偷偷回退到另一声音。

用 `ffprobe` 或实际解码测量片段长度后排时间，不能用单词数估时冒充真实时间。案例保留 0.8 秒片头／片尾，每 cue 后 0.3 秒，加上文稿指定的思考停顿。这是节奏选择，不是每门课的固定配置。

```json
{
  "id": "en_gb",
  "duration": 42.16,
  "segments": [
    {"id":"measure_box", "start":0.8, "end":8.12, "sceneEnd":8.42}
  ]
}
```

上面是结构示例，不是可用成片时钟。`end` 是讲话结束，`sceneEnd` 是该画面停留结束。必须有有限、递增、正时长的时间值；声音之间使用同一 cue ID 集合及顺序。某种语言更长时，让画面窗口更长，保留自然语音；不要整段拉快语言以强求影片同长。

如果只改一段文字，重新生成对应缓存，再重建该声音之后的时间轴、字幕、章节和画面拼接。修改了仅字幕换行则不必重做声音和视频。使用源文件依赖关系决定重建范围，避免交付新字幕配旧时钟。

## 混音与 BGM

分别保存原始旁白、规范化旁白、音乐和最终混音，防止音乐与讲解永久焊死。案例采用 48 kHz 单声道 WAV 和 FFmpeg `loudnorm=I=-17:TP=-2:LRA=7` 作为旁白目标，然后叠加很低的原创 pluck 音乐。这些是工作参数，最终仍需检查真实混音峰值、响度和清晰度；参数本身不能证明音频通过。

音乐可使用自制合成声部或许可明确的第三方录音。第三方资源记录作者、曲名、下载来源、许可证、署名要求和实际文件；“免费试听／下载”不自动意味着能用于公开课程。原 Placement 最终是程序生成的稀疏拨弦与持续和声，**没有下载第三方 BGM**，不能写成已搜索并使用某热门配乐。

先用低音乐电平、淡入淡出听清讲解；信息密集处可以进一步降低或侧链压低。避免鼓点掩盖辅音，避免旁白停顿时音乐突然抢戏。试听片头、术语最密段、解释停顿和片尾。数值检查有助于发现削波，但不能代替审听；没有实际听取时只报告技术验证。

## 同一声音支持所有字幕语言

声音与字幕是两条独立选择轴。四种配音 × 七种字幕意味着 28 个由所选声音时钟派生的字幕文件，不是七份字幕硬套四个相同秒数。推荐 manifest 显式列出每声音的视频、timing 和语言→VTT 路径，字幕还要有 `Off`。

先维护按 cue ID 的英文／中文文稿、额外翻译和术语表。数字、否定、单位、固定点、模式和容量必须保持。译文允许自然表达，不强行照搬英文词序。可用字幕内容的数字 token 检查、术语检查和行长检查发现低级错误，但它们不证明译文由母语者审校。

如果没有词级跨语言对齐数据，可在同一语义 cue 的讲话时窗中按阅读长度分配短字幕，明确称“语义对齐／近似分段”，不能声称逐字同步。案例每段尽量两行：西文约 43 字符／行、中日文约 24、韩文约 28；实际应由屏幕大小、字体和阅读速度调整。原实现为短字幕预留最多约 1.15 秒基础时长，再分配剩余时间，不是强制每段都能停满某个秒数。

字幕生成必须保护数字，至少覆盖三层：

1. 句子切分：`48.1` 中的点不是句号。
2. cue 分块：不能把数字的一半分进下一条字幕。
3. CJK 自动换行：不能在 `48.5` 或 `48,1` 内换行。

使用数字 token（例如 `\d+(?:[.,]\d+)*`）识别不可断位置，同时防止短尾词闪一下、空字幕、零长度字幕和越过 cue 结束。至少加入小数点、小数逗号、单位、百分号、缩写与长日韩句的回归样例。不要机械地移除中日字幕中的全部空格；只处理生成器插入的换行。

## 字幕位置与播放器协调

密集教学图表的底部经常还有指标，浏览器原生字幕和控制条会压住它们。Placement 使用如下方式：

- 普通网页：选中 `TextTrack.mode='hidden'`，从 `activeCues` 读取文字，显示到视频画面下方的独立字幕条。
- 关闭字幕：所有轨道 `disabled`，字幕条隐藏。
- 全屏：选中轨道切换为 `showing` 使用原生字幕，外部条隐藏；退出后恢复。
- `cuechange`、`load`、`timeupdate`、`seeked` 更新字幕。切换声音时保留字幕语言和速度。

额外预留画面安全区仍然有价值，因为原生全屏字幕无法使用画面下方的网页条。验证至少覆盖西文长句、中文、日文／韩文的移动端显示，原生全屏往返和快进后的字幕更新。

切换声音时按 `{cueId, progress}` 找到新声音对应时间，而不是保留相同秒数。用户连续切两次声音、在加载途中点章节、暂停状态切换和恢复播放都需处理；用请求标识排除旧媒体事件，加载期间禁用“转入实验室”，防止传递错时钟状态。

## 必须留在交付记录中的界限

记录哪些声音是真实生成、哪种语言经过何种校验、字幕如何分段、音乐来源和哪些素材未打包。不要把可选择的菜单当成文件已经存在的证据。实际检查所有最终 MP4 是否含可解码音轨、字幕是否加载，以及章节是否使用当前声音时钟。自动解码与波形相关性是技术证据；自然感、翻译质量与知识清晰度仍需独立判断。
