# 科学家角色、手势与实验点评

在需要卡通讲解员或实验室陪伴者时阅读。角色是教学界面的组成部分，不应成为遮挡图形、持续抖动或不真实赞扬的来源。相关代码在 [scientist-rig.js](../assets/placement-lesson06-source/course/scientist-rig.js) 与 [mentor.js](../assets/placement-lesson06-source/course/mentor.js)。

## 角色选择与素材记录

匹配画面年龄感、性格、语速与选定的声音；不用“老人”就必须降调或变慢的刻板规则。先试听一段包含术语、提问、轻松句子的真实讲稿，再看角色说这段话是否自然。选择服务音色不等于复刻真实科学家、主播或企业家的声音。

Placement 使用 [j4p4n 的 Einstein 矢量画](https://openclipart.org/detail/302755/einstein)，原作者在 Openclipart 的素材记录指向 [CC0 1.0](https://creativecommons.org/publicdomain/zero/1.0/)。提取头部后新增了可动身体、手势、闭嘴微笑和白胡子。保留原素材、来源、许可链接和改造记录；不要把可见于网络误写成开源许可。

本课程用户明确选择闭嘴角色：源图的露齿笑形只替换一次，不能在其上叠一个新嘴造成双层表情。嘴形固定，胡子两瓣轻微抬起／卷动即可。角色参数应允许这个约束通过组件统一生效，避免片头改了而实验室仍使用旧脸。

## 先定义手要到哪里，再求胳膊如何弯

独立旋转两个手臂常导致肘部翻转、手不接触物体、两只手不同步。可以采用解析的二维双骨 IK：给肩关节 `S`、目标手腕 `W`、上臂长度 `L1`、前臂长度 `L2`，求肘关节 `E`。

令 `d = |W − S|`。将可达距离限制在 `|L1−L2| + ε` 与 `L1+L2−ε` 之间，沿原方向得到实际手腕 `W'`，避免过伸和除零。然后：

```text
u = (W' − S) / d
n = (−u.y, u.x)
a = (L1² − L2² + d²) / (2d)
h = sqrt(max(0, L1² − a²))
E = S + a*u + bend*h*n
```

`bend` 为 `+1` 或 `−1`，由该侧手臂／手势固定选择。插值过程中不要随意切换这个符号，否则肘部会突然翻面。上臂方向来自 `E−S`，前臂方向来自 `W'−E`；SVG 若使用向下为零角度的局部坐标，需要一致地转换角度。案例骨长为 73／65 个局部单位，仅是角色比例参数。

这一方法受 [Blender 官方 IK 说明](https://docs.blender.org/manual/id/5.1/animation/constraints/tracking/ik_solver.html) 中“目标控制末端、控制弯曲方向”的概念启发；实际程序为独立 JavaScript 解算器，不依赖 Blender 运行时。

## 手势从表演意图出发

将姿势保存成手腕目标、手形、掌心角度和头部倾角，例如 `welcome`、`point`、`think`、`count`、`spread`、`balance`、`wave`。同一个归一化进度控制双手和头部，使用 `3p²−2p³` 等平滑曲线。手腕路径可加浅弧：

```js
const wrist = [
  lerp(from[0], to[0], p),
  lerp(from[1], to[1], p) - Math.sin(Math.PI * p) * arcHeight
];
```

动作分为准备、到位、保持、收回。重点在**保持**：指向标签、托住卡片或表达两边取舍时，支撑的手要停住，不能继续正弦晃动。循环只用于明确的挥手、走路或必要的轻微呼吸。换姿势使用 `fromPose`，不要每个 cue 都瞬间回到垂手默认姿势。思考时手可能在头部之前，其他手势在身体之后，层级也应随姿势确定。

全身模式预留伸展手臂的外边界；不能只按躯干宽度裁剪。案例身体名义画布为 240 × 480，但伸出的双手可达 x≈−65…305。图表密集场景用 160 × 160 左右的头像；人物大小、说话气泡和指向目标保持明确关系。

## 小幅胡子运动不等于口型同步

案例最大抬升为源 SVG 的 0.24 个单位、胡子尖旋转约 0.7°。这些数字需按新角色比例调整，不是普适标准。

声音包生成过 25 Hz 的纯人声 RMS envelope，适合为每个声音单独驱动轻微表情。但完成版为了让语义片段可直接按时长重排，默认使用 cue 进度下的小幅表达性运动。`film-art.js` 的 `s.mouth` 可覆盖默认值，实际默认值是小幅 `sin²` 波动。**不要因为 envelope 文件存在，就声称成片使用了逐字口型或音素同步。**

若未来确实使用音量驱动的角色，再渲染每个声音的角色层，或对每个声音整片重新渲染。把一份已带口型的画面直接拉伸到另一种语言，通常无法保留口型含义。

## 点评是领域逻辑的可读表达

交互科学家可以完全在本地工作，无须每次拖动调用语言模型。输入应包括当前状态、动作前的完整状态、动作类型、被操作对象、实验模式和容量；输出结构化点评：

```js
{
  tone: 'thoughtful',
  title: 'Shorter wires, still crowded.',
  lines: ['HPWL 52.0 → 49.2.', 'Overflow is still 2.'],
  highlightBin: 0,
  suggestion: { cell: 'B', target: {x: 6, y: 2}, metrics: {/* computed */} }
}
```

上面的数字是结构示例，产品中必须计算。点评根据两项指标及约束，而不是只看“用户刚动了鼠标”就说很好：

| 观察 | 合适的点评方向 |
| --- | --- |
| 溢出下降且达到零 | 容量条件已满足，再报告线长取舍 |
| 溢出下降但未达到零 | 进步了，仍有具体拥挤区域 |
| 线长下降但溢出仍大于零 | 更短，但容量问题还没解决 |
| 溢出上升 | 哪个区域变得过满，提示换一个实验 |
| 指标都不变 | 解释包围盒极值或 bin 归属可能未改变 |
| 刚从视频导入或加载预设 | 客观描述当前布局，不假装学生取得了进步 |

建议动作先在克隆状态上运行，计算实际结果并确认固定点不变，再展示“如果移动到这里，指标会是多少”。候选位置应可见、可抓取，避免新点完全叠在已有点上。可以把减少溢出的候选按线长排序，但称作“一种可尝试的移动”，不称全局最优，也不要未经用户操作就自动执行。

比较基准是**本次拖动开始前**的状态，不是上一帧 pointermove；这样才能解释一个完整动作。拖动中更新图和数值，结束后再稳定更新短点评，避免气泡每帧重排。使用 `textContent` 或转义插入文本，保持键盘焦点，减少动态效果偏好下不自动平滑滚动。

参考算法模式与可行性练习可能使用不同条件。容量为一且总容量不足时，不能继续催促学生“做到零溢出”；应解释下界、当前结果及可观察的迭代。练习通过条件判断约束和指标，允许多个正确布局。
